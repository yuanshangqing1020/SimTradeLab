## 2. 策略概要（v0.7）


| 项    | 内容                                                  |
| ---- | --------------------------------------------------- |
| 平台   | 聚宽 JoinQuant，分钟级 `handle_data`                      |
| 标的   | 5 只 ETF：纳指、黄金、中证500、**中证1000**、创业板                  |
| 格距   | 3% 对称（`buy_drop` / `sell_rise` = 0.03）              |
| 底仓   | 每只初始约 5 万元（`base_value=50000`）                      |
| 网格单格 | 每格约 5000 元（`grid_value=5000`），**成交后按现价重算股数**        |
| 破顶   | level≤**-5** 且再涨 → **提前破顶**（v0.7 新增）；level≤-8 为卖尽破顶 |
| 手续费  | ETF 万一免五（`min_commission=0.1`）                      |
| 初始资金 | 50 万（分析脚本默认 `--initial-cash 500000`）                |


**v0.7 定位：** 在 v0.6 验证 1000 高潜力的基础上，修复 `grid_shares` 长期不更新导致的卖侧停摆，并增强可观测性（WARN 日志），作为 **可实盘的生产候选**。

## 3. v0.7 相对 v0.6 的代码差异


| 改动               | v0.6         | v0.7                                   | 目的                         |
| ---------------- | ------------ | -------------------------------------- | -------------------------- |
| `grid_shares` 更新 | 仅建仓/破顶时重算    | **每次成交后** `_refresh_grid_shares()`     | 价格涨 N 倍后每格仍≈5000元，避免股数过大卖光 |
| 破顶阈值             | level≤-8 才破顶 | **level≤-5** 提前破顶（`early_break_level`） | 牛市不必连卖 8 格才重置，减少持仓被掏空      |
| 跳过日志             | 静默跳过         | **WARN**：建仓/加仓/止盈跳过                    | 现金不足、股数不足、满格时显式告警          |
| 破顶日志             | `【破顶】`       | `【破顶-提前】` / `【破顶-卖尽】`                  | 区分两种破顶路径                   |


核心新增函数：

```python
def _calc_grid_shares(price):
    shares = int(g.grid_value / price / 100) * 100
    return shares if shares > 0 else 100

def _refresh_grid_shares(status, price):
    status['grid_shares'] = _calc_grid_shares(price)
```

破顶分支逻辑变更：

```python
# v0.6: level > max_sell_level(-8) 才逐格卖
# v0.7: level > early_break_level(-5) 才逐格卖，否则提前破顶
if level > g.early_break_level:   # -5
    ...  # 正常止盈
else:
    ...  # 破顶升维（提前 or 卖尽）
```

## 6. v0.6 问题与 v0.7 修复对照

> 详见 [v0.6 SUMMARY 第 7 节](../v0.6/SUMMARY.md#7-关键问题1000etf-为何-2025-11-后停止交易)

### 6.1 v0.6 根因（简要）

1. `**grid_shares` 自 2021 破顶后 4 年未更新**：1000 从 ~1 元涨到 ~3 元，仍按 5000 **股**/格卖（≈1.5 万元/格，设计值 3 倍）。
2. **2025 牛市连续大格止盈**：持仓从 2 万+ 股降至 1633 股，低于 grid_shares=5000 → 涨也卖不出。
3. **level=-4 未达 -8**：不触发破顶，无法重算 grid_shares → **静默停摆 175 天**。

### 6.2 v0.7 修复效果


| 修复项               | 效果                                             |
| ----------------- | ---------------------------------------------- |
| 成交后重算 grid_shares | 1000 在 2.97 元时 grid_shares≈1600 股，与 5000 元设计一致 |
| 提前破顶 level≤-5     | 33 次提前破顶，避免连卖至持仓枯竭                             |
| WARN 日志           | 止盈/加仓/建仓跳过时显式记录（本回测 WARN 0 次，说明修复后未再触发）        |
| 1000 末次交易         | 2026-05-21 仍正常加仓，**无停摆**                       |

## 10. 后续改进方向（v0.8+）

v0.7 解决了 **卖侧停摆**，但 v0.1 起提出的 **买侧满格防冻结** 仍未实现（当前靠换池回避）。

### P0 — 买侧防冻结（v0.1 起未落地，换池失效时仍需）


| 方案          | 说明                                      |
| ----------- | --------------------------------------- |
| **满格锚价追踪**  | level=+10 后允许 `ref_price` 随下跌下移，止盈线跟随市价 |
| **按仓位比例限仓** | 「单标的市值 / 总资产 ≤ Y%」替代固定 10 格             |
| **破底重置**    | 加满格且再跌 N 格时减仓至底仓或休眠                     |


### P1 — 参数微调

- 1000/创业板可试 **3–4% per-标的格距**；提前破顶阈值 -5 vs -6 可再扫。
- 黄金末次 level=+4，可关注是否接近买侧上限。

### P2 — 标的池

- 300ETF 与 500ETF 相关性较高；1000 与 500 亦有重叠——可考虑红利/国债 ETF 进一步分散。
- 每季度检查 level、末次活跃日；level=+8 预警。

### P3 — 可观测性与评估

- `record()` 增加各标的 level、grid_shares、冻结/停摆标志。
- 除做 T 利润外，跟踪分标的总收益、资金利用率、有效网格活跃率。

## 12. 结论

**v0.7 在 v0.6 的 1000 标的池上修复 `grid_shares` 动态更新与提前破顶，七年总落袋 13.98 万（比 v0.6 低 5.5%，但 1000 从 175 天停摆恢复至全程活跃），末态 5/5 全部正常，是七版中首个可实盘的生产候选。**

七版完整实验结论：

1. **格距（v0.1–v0.3）**：3% 为综合最优；继续加宽边际收益递减。
2. **换池（v0.4–v0.5）**：移除医药/中概消除买侧冻结，后期落袋显著改善。
3. **1000 实验（v0.6）**：增量巨大但暴露机制 bug，**不可直接实盘**。
4. **机制修复（v0.7）**：grid_shares 重算 + 提前破顶，修复卖侧停摆，**推荐作为当前生产配置**。
5. **买侧防冻结**（满格锚价追踪等）仍待 v0.8，以防未来新标的长熊复发。

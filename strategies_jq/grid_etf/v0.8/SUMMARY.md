## 2. v0.8 相对 v0.7 的核心变更

| 项 | v0.7（相对偏移） | v0.8（绝对格数） |
|----|----------------|----------------|
| 建仓后 level | **0**（标准底仓档） | **`pending_base` 待确认 → 到账后同步** |
| 加仓 | level **+1** | level **+1** |
| 止盈 | level **-1** | 成交后 **`_sync_level_after_trade` 按持仓重算** |
| level 含义 | 相对底仓偏了几格 | **当前持有几格** |
| level = 0 | 底仓档（约 5 万） | **清仓** → 清除 `grid_status` → 重装 |
| 破顶 | level≤-5 提前 / ≤-8 卖尽 | **移除**（卖到底 → 清仓 → 重装） |
| 加仓上限 | level ≤ +10 | level ≤ **20**（10 底仓 + 10 额外） |

**设计动机：** 消除 v0.7 中 level 与真实持仓脱节导致的卖侧停摆（见 [v0.7 §6.3](../v0.7/SUMMARY.md#63-level-语义level0-还是-level10)）。

## 3. level 语义（v0.8.5）

```
base_level = base_value // grid_value = 10

重装：level=0 + pending_base=True
  ↓ 到账 → 【底仓到账】按持仓同步 level
  ↓ 涨 3% → 【止盈】/【止盈（部分）】→ 按剩余持仓重算 level
  ↓ level=0 → 【清仓-碎股】/【清仓】→ 【重装建仓】
  ↓ 跌 3% → 【加仓】level += 1

每 bar：level > 持仓可支撑格数 → 【等级校准】下调
不足 1 格但有货（≥100 股）→ 视为 1 格（防误清仓）
```

| level | 含义 |
|-------|------|
| **≈10** | 满底仓（5 万市值） |
| **11 ~ 20** | 底仓 + 额外加仓 |
| **1 ~ 9** | 部分卖出后持有 |
| **0** | 清仓；碎股卖清后退出 |

## 8. 相对 v0.7 的优劣

### 优势

1. **1000ETF 长跑不停摆**：47k vs 8k（2015 扩展），末次 2026-05-21
2. **5/5 全程活跃**，无卖侧股数不足僵死
3. **level 与持仓绑定**，末态 level ≈ 持仓 // grid_shares
4. **总量显著高于 v0.7**（2015 扩展 +96%，2019 起点 +85% 量级）

### 代价

1. **无破顶**：牛市卖光后清仓重装，重装 29 次 vs v0.7 的 5 次
2. **2015 年利润占比高**（约 25%），与同日多标的建仓有关
3. **等级校准 416 次**：加仓 `level+=1` 与 T+1 到账存在 1 格暂态偏差，每 bar 自动修正（不影响交易，仅日志噪音）

## 9. 代码要点

```python
def _share_grids_from_amount(total_amount, grid_shares):
    share_grids = total_amount // grid_shares
    if share_grids == 0 and total_amount >= 100:
        return 1  # 不足 1 格但有货
    return share_grids

# 止盈后按持仓重算，而非 level -= 1
_sync_level_after_trade(status, total_amount)

# 每 bar 校准（仅下调）
_calibrate_level_from_position(status, total_amount, grid_shares)
```

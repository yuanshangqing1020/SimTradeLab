## 2. 策略概要（v0.6）

| 项 | 内容 |
|----|------|
| 平台 | 聚宽 JoinQuant，分钟级 `handle_data` |

**v0.6 定位：** 验证 screener 高分标的 **中证1000** 能否进一步提升 v0.5 组合落袋；同时暴露 **`grid_shares` 长期不更新** 的机制缺陷。

## 7. 关键问题：1000ETF 为何 2025-11 后停止交易

> 本节是 v0.6 最重要的诊断结论。  
> **不是** v0.1–v0.3 的「加满格冻结（level=+10）」，而是 **「卖侧股数不足 + 锚价死区」** 新型停摆。

### 7.1 现象

| 项 | 数据 |
|----|------|
| 末次交易 | **2025-11-27**（止盈 @ 2.963 元） |
| 回测结束 | 2026-05-21 |
| 沉默时长 | **175 天** |
| 末次等级 | **-4**（卖侧超卖，非买侧满格） |
| 同期其他 4 只 | 均持续交易至 2026-05 |

### 7.2 末次成交后网格快照

| 变量 | 值 | 含义 |
|------|-----|------|
| `ref_price` | **2.963** | 网格锚价 |
| `level` | **-4** | 相对底仓已多卖 4 格 |
| 持仓 | **1633 股**（约 4,839 元） | 仅为 5 万底仓的 **9.7%** |
| `grid_shares` | **5000 股**（未更新） | 卖一格需要 5000 股 |
| 触发加仓 | 价格 ≤ **2.874**（-3%） | |
| 触发止盈 | 价格 ≥ **3.052**（+3%） | |

### 7.3 根本原因一：`grid_shares` 自 2021 年起未更新

策略中 `grid_shares` **仅在建仓和「破顶」时重算**，普通止盈/加仓不会更新：

```136:137:SimTradeLab/strategies_jq/grid_etf/v0.6/grid_etf_v0.6.py
                    new_grid_shares = int(g.grid_value / current_price / 100) * 100
                    status['grid_shares'] = new_grid_shares if new_grid_shares > 0 else 100
```

| 时间点 | 价格 | 应有 grid_shares | 实际 grid_shares |
|--------|------|-----------------|-----------------|
| 2021-06-16 末次调整后 | ~0.96 元 | ~5,000 股 | **5,000 股** ✓ |
| 2025-08 牛市 | ~2.97 元 | **~1,600 股** | **5,000 股** ✗ |

1000ETF 末次「破顶」在 **2021-06-10**，之后 4 年价格从 ~1 元涨到 ~3 元（约 3 倍），但 `grid_shares` 一直停在 5000 股。  
按设计每格 5000 **元**，实际每格卖出 5000 **股** × 2.97 元 ≈ **14,850 元**，是设计值的 **3 倍**。

### 7.4 根本原因二：连续大格止盈 → 持仓不足以卖一格

2025 年 7–8 月牛市中，1000 连续 6 次以 5000 股/格卖出：

```
2025-07-17  止盈 @ 2.635  持仓 21633 → 16633
2025-07-28  止盈 @ 2.715  持仓 16633 → 11633
2025-08-11  止盈 @ 2.797  持仓 11633 → 6633
2025-08-15  止盈 @ 2.881  持仓  6633 → 1633   ← 几乎卖光
2025-08-21  止盈 @ 2.968  持仓  1633
```

止盈前置条件（源码）：

```98:100:SimTradeLab/strategies_jq/grid_etf/v0.6/grid_etf_v0.6.py
                if level > g.max_sell_level:
                    position = context.portfolio.positions[ticker]
                    if position.closeable_amount >= grid_shares:
```

**1633 < 5000 → 即使价格涨过 3.052，也无法卖出，且无 WARN 日志。**

9 月、11 月各出现一次「跌 3% 加仓 5000 股 → 反弹止盈」的小循环；11-27 最后一次止盈后，持仓又回到 1633 股，再次陷入卖不出状态。

### 7.5 机制示意图

```
2021 破顶 grid_shares=5000（价~1元，合理）
        │
        │  4 年牛市价涨 3 倍，grid_shares 未缩小
        ▼
2025 每格卖 5000 股（~1.5 万元/格，而非 5000 元/格）
        │
        │  7–8 月连续 6 次大格止盈
        ▼
持仓降至 1633 股（底仓 9.7%）
        │
2025-11-27 后：
  ├─ 涨 ≥ 3.052？ → 想止盈，1633 < 5000 → ❌ 静默跳过
  └─ 跌 ≤ 2.874？ → 未跌够则不加仓 → ❌
        │
   网格停摆 ~6 个月（level=-4，非 level=+10）
```

### 7.6 与 v0.1 医药/中概冻结的对比

| | **买侧满格冻结（v0.1）** | **卖侧股数不足停摆（v0.6 1000）** |
|--|------------------------|--------------------------------|
| 触发等级 | level = **+10** | level = **-4** |
| 触发行情 | 长熊连跌 | 长牛连涨后 |
| 直接原因 | 加满格，`ref` 锁死 | `grid_shares` 过大 + 持仓卖光 |
| 能否止盈 | 价格回不到 ref×1.03 | 价格到了也 **股数不够** |
| 破顶能否救 | 否（level 远高于 -8） | 否（level 未达 -8） |
| 日志 | 无后续记录 | **同样无 WARN** |

### 7.7 为何 screener 高分但回测停摆

- screener 日线模拟假设 `grid_shares` 始终随价格合理缩放
- v0.6 实盘逻辑中 **`grid_shares` 多年不更新**，牛市涨 3 倍后每格过大
- 1000 小盘 2024–2025 涨幅大，连续止盈却不触发「破顶」（需 level≤-8），永远没有机会重算 `grid_shares`

## 8. v0.7 改进方向

v0.6 证明 1000 **潜力极大**（55,855 元单标的利润），但 **必须修复机制** 才能用于生产。

### P0 — 修复 grid_shares（必须，v0.1 起未落地）

| 方案 | 说明 |
|------|------|
| **每次成交后重算 grid_shares** | `int(grid_value / current_price / 100) * 100`，随价格自动缩放 |
| **卖出/买入失败打 WARN 日志** | `closeable < grid_shares` 或现金不足时显式记录 |
| **破顶阈值提前** | 可选：level≤-5 且价格再涨 N% 也触发 grid 重置 |

### P1 — 1000 参数微调

- 1000 波动大于 300/500，可试 **4% 格距** 减缓连续卖出速度
- 或 per-标的格距：1000/创业板 3–4%，红利类 2.5%

### P2 — 机制层防冻结（v0.1 起未落地，仍必须）

- 满格锚价追踪（买侧 level=+10）
- 按仓位比例限仓
- 见 [v0.1 SUMMARY 第 8 节](../v0.1/SUMMARY.md#8-v02-改进方向建议优先级)

### P3 — 组合建议

| 方案 | 标的池 | 适用 |
|------|--------|------|
| **v0.7-A** | v0.5 池 + 修复 grid_shares | 稳健生产候选 |
| **v0.7-B** | v0.6 池（1000 替 300）+ 修复 | 进攻型，需验证修复后 1000 不再停摆 |
| v0.6 现状 | 不修复 | **不可直接实盘** |

## 10. 结论

**v0.6 以 1000ETF 替换 300ETF，七年总落袋 14.79 万（六版最高，比 v0.5 高 34.8%），但 1000 在 2025-11-27 后停摆 175 天——根因是 `grid_shares` 自 2021 年以来未随涨价缩小，连续大格止盈后持仓不足以卖一格。**

六版完整结论：

1. **格距**：3% 为综合最优（v0.2/v0.5/v0.6 验证）。
2. **换池**：移除医药/中概有效（v0.4）；1000 替 300 增量巨大但需机制修复（v0.6）。
3. **冻结有两种**：买侧满格（v0.1）和卖侧股数不足（v0.6 1000）——均需 v0.7 修复。
4. **v0.7 路径**：保留 1000 + **每次成交重算 grid_shares** + WARN 日志，再跑回测验证 11 月后是否恢复交易。
5. **不可直接实盘 v0.6**：总量好看，但 1000 末 6 个月网格失效，且同类 bug 可能潜伏于任何长期牛市未破顶的标的。

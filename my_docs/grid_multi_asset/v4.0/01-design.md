## 1. 目标与非目标

### 1.1 目标

在 **仅现货多头** 前提下，使策略具备**可对盘方承诺、可用三段窗口同时检验**的「实战性」：

- **I — 全长风控：** 固定起点与截止日下的 **最大回撤** 满足红线。  
- **II — 全长相对基准：** 相对 **沪深300（`000300.SS`）** 的 **超额收益与信息比** 满足底线（避免「v3 全长」类大幅跑输）。  
- **III — 近年表现：** 与历史文档一致的 **Holdout**（或之后修订的「近年窗」，须写死日期）上，业绩指标满足底线，避免仅用全长或仅用短窗定参。

上述三维 **同时为 v4 选参/验收的必要条件**（三重门禁）。Walk-Forward 综合分 **只做初筛或次要排序**，不得作为唯一决定是否上线的指标。

### 1.2 非目标

| 类别 | 说明 |
|------|------|
| 衍生品 / 做空 / Beta 对冲腿 | 与 v3 设计一致：不纳入 v4.0 |
| 与 JoinQuant 双轨同步 | 不强制；SimTradeLab 为规格与实现真源 |

## 2. 三重门禁（I / II / III）— 统一定义

以下窗口与 **SimTradeLab `run_backtest.py`**、基准 **000300.SS**、初始资金（默认 **50 万**，与前三版一致）绑定；若变更须在 `03-optimization-summary.md` 中显式记录。

### 2.1 窗口

| 代号 | 区间（可调校准，但须写死） | 用途 |
|------|---------------------------|------|
| **FULL** | `2019-01-01` ～ 约定截止日（与 v2/v3 全长横比时对齐） | **I、II** 的主裁判 |
| **RECENT** | `2025-01-01` ～ `2026-03-31`（与 v1～v3 Holdout 一致） | **III** |
| **BEAR** | `2021-01-01` ～ `2022-12-31`（与 v3 熊市专项一致） | **监控 + 报告**；首轮可不作为 hard gate，若 FULL/RECENT 已过关仍建议披露 |

### 2.2 指标与「无解」时的处理原则

任何通过 Optuna 得到的参数集合，须在 **同一套回测实现** 上计算：

| 门禁 | 指标（建议实现名与 stats 模块一致） | 首轮建议红线（**待首次 v4 回测校准**，可收紧） |
|------|------------------------------------|-----------------------------------------------|
| **I** | FULL 区间 **最大回撤** ≤ 阈值（注意阈值为负数，例如 ≤ **−38%** 表示回撤不深于 38%） | **≤ −38%**（略优于 v2 全长约 −39.8%）；若窄 ETF 基线仍困难，放行到 **−40%** 须在总结中说明 |
| **II** | FULL 区间相对 000300：**超额收益率** ≥ 下限；**信息比率** ≥ 下限 | 超额 ≥ **−10%**（优于 v2 约 −9.6% 时略收紧或对齐，以全样本复算为准）；IR ≥ **−0.05**（弱于 v2 的 −0.063 时视为改善） |
| **III** | RECENT：建议同时满足 **年化收益率** ≥ **+20%**、**最大回撤** ≥ **−18%**、**夏普** ≥ **1.2**（均为「不低于 v2 Holdout 量级、留余地」的起步线） | 若结构上 RECENT 与 FULL/II 冲突，**禁止仅用 RECENT 定版**；须记录 Pareto 折中 |

**三条同时不成立：** 若在给定策略结构下 **不存在** 同时满足 I+II+III 的离散参数，则：

1. 在总结中写明 **「当前结构下三重门禁不可行」**；  
2. 按优先级 **收紧/放宽**：默认顺序为 **先保 I，再 II，再 III**（风控 → 全长基准 → 近年窗），每一步放宽须有文档与数值记录；或  
3. 升级结构（如 **窄 ETF 池**、**周频 regime**、**路线 C 双层资金**）再重新搜索。

## 3. 优化与选参流程（相对 v1～v3 的强制变更）

1. **搜索阶段：** 保留 Optuna + Walk-Forward（时间与 v2 对齐或可缩短试验），目标函数可仍为原综合分 **或** 改为「FULL 多目标加权」，但 **不作为最终录取依据**。  
2. **复核阶段：** 对每个 **COMPLETE** 且 WF 分达阈值的 trial（或对 Top-K  trial），自动跑 **FULL + RECENT**（及建议 BEAR）三段回测，提取上表指标。  
3. **录取：** 仅当 **I ∧ II ∧ III** 全部满足时标记 **v4_eligible**；取其中 WF 分最高或 FULL 卡玛最优者为「候选默认参数」，**禁止**出现「仅 Holdout 好、FULL 崩」的定版。  
4. **人工审核：** 在 `03-optimization-summary.md` 中 **并列** 三张表（FULL / RECENT / BEAR），并对比 v2 Trial 29 同口径。

## 4. 策略结构（默认实施方案）

与头脑风暴一致：**路线 B（窄 ETF Universe）+ 路线 A（门禁选参）** 为 v4 **默认主路径**；v2 逻辑为内核。

| 模块 | v4 默认 |
|------|---------|
| Regime | 沪深300 相对 MA120/MA250 → BULL / NEUTRAL / BEAR；**invested_ratio** 三档与 v2 一致或可参与离散搜索 |
| **Regime 刷新** | **周频**更新 `invested_ratio`（不必换股）；换股仍按 `REBALANCE_FREQ`；首轮实现时二选一须有对照日志一条 |
| Universe | **主：** `DEFENSIVE_ETF_POOL` 扩展为 **3～8 只高流动性宽基/红利 ETF** 固定池（常量表维护）；**分支：** 保留「宽池」仅作研究，不得作为默认上线 |
| 网格 | 与 v2 相同：`GRID_STEP_*`、`GRID_MAX_LAYER`、`LAYER_FRACTION`、单票 water-filling |
| v3 专有 | **默认不启用** `BEAR_UNIVERSE_MODE` / `BEAR_GRID_MODE` 大面积搜索；若窄 ETF 主路径 I/II 仍失败，再单列小试验 |

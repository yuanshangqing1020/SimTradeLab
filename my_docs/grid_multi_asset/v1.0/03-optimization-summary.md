## 一、调参设计原理

### 1.1 Walk-Forward 滚动优化

本次调参采用 **Walk-Forward Analysis（滚动向前验证）** 而非简单的单段回测优化，核心目的是防止过拟合。

```
时间轴示意：
2019  2020  2021  2022  2023  2024  2025  2026
├─────────────────────────────────────────────┤
│  优化区间（训练+测试）    │  Holdout（样本外）│
│  2019-01 ~ 2024-12       │  2025-01~2026-03  │
└──────────────────────────┴───────────────────┘

Walk-Forward 7个滚动窗口（训练24月 / 测试6月 / 滑动6月）：
窗口  训练期                    测试期
W1    2019-01 ~ 2021-01        2021-01 ~ 2021-07
W2    2019-07 ~ 2021-07        2021-07 ~ 2022-01
W3    2020-01 ~ 2022-01        2022-01 ~ 2022-07
W4    2020-07 ~ 2022-07        2022-07 ~ 2023-01
W5    2021-01 ~ 2023-01        2023-01 ~ 2023-07
W6    2021-07 ~ 2023-07        2023-07 ~ 2024-01
W7    2022-01 ~ 2024-01        2024-01 ~ 2024-07
```

**每个 trial 的流程：**
依次跑完 W1→W7 的训练+测试，以 7 个测试期得分的均值减去稳定性惩罚（波动率×0.5）作为该 trial 的最终综合得分。

### 1.2 综合评分公式

```
综合得分 = Sharpe×0.40 + (−MaxDrawdown)×0.30 + IR×0.20 + WinRate×0.10
最终得分 = 测试期均值 − std(测试期得分) × 0.5
```

| 指标 | 权重 | 理由 |
|---|---|---|
| 夏普比率 | 40% | 风险调整后收益，已隐含年化信息 |
| 最大回撤（取负） | 30% | 量化策略核心风控指标 |
| 信息比率 | 20% | 相对基准的超额能力 |
| 胜率 | 10% | 确保交易质量 |
| 稳定性惩罚 | 减项 | 避免只在特定市场环境有效 |

### 1.3 Optuna TPE 贝叶斯优化

- **采样器：** TPESampler（Tree-structured Parzen Estimator）
- **目标：** maximize（得分越高越好）
- **早停：** 连续 `参数空间 ÷ 4 = 972` 次（含剪枝）无改进则自动终止
- **剪枝：** 第 4 个测试窗口（step ≥ 3）后上报中间值，低于阈值提前终止当前 trial
- **断点续传：** 状态保存在 `optimization/results/optuna_journal.log`，中断后重跑自动续接

## 二、参数空间

共 8 个可调参数，总组合数 **3,888 种**：

| 参数 | 候选值 | **最优值** | 含义 |
|---|---|---|---|
| `MAX_HOLD` | 10, 20, 30, **50** | **50** | 最大持仓标的数 |
| `GRID_STEP_VOL_FACTOR` | 0.30, 0.45, **0.60** | **0.60** | 步长波动率放大系数 |
| `GRID_STEP_MIN` | **0.01**, 0.02 | **0.01** | 网格步长下限（1%） |
| `GRID_STEP_MAX` | 0.03, **0.05** | **0.05** | 网格步长上限（5%） |
| `GRID_MAX_LAYER` | 2, **3**, 4 | **3** | 最大偏离层数 |
| `LAYER_FRACTION` | **0.08**, 0.12, 0.16 | **0.08** | 层间仓位权重增量 |
| `VOL_WEIGHT` | 0.50, 0.65, **0.80** | **0.80** | 波动率在标的评分中的权重 |
| `REBALANCE_FREQ` | 5, 10, **20** | **20** | 换股频率（交易日） |

**约束：** `GRID_STEP_MIN < GRID_STEP_MAX`（否则自动拒绝该 trial）。

### 4.2 最优参数（Trial 53，修复 bug 后第三次优化）

> **注：** 原第一次优化（Trial 33，score=-0.5790）因 `get_fundamentals` 列名 bug（`pe_ratio`/`market_cap` → 应为 `pe_ttm`/`total_value`）导致股票全部被过滤，策略实质退化为纯 ETF 模式，参数无效，已归档至 `results/archive_v1_buggy_etf_only/`。修复 bug 并清除缓存后重新优化，以下为第三次优化的阶段性最优值。

```python
context.MAX_HOLD             = 10    # 精选 10 只高质量标的，集中持仓
context.GRID_STEP_VOL_FACTOR = 0.45  # 步长波动率放大系数（适中）
context.GRID_STEP_MIN        = 0.01  # 步长下限 1%
context.GRID_STEP_MAX        = 0.05  # 步长上限 5%
context.GRID_MAX_LAYER       = 2     # 最多 2 层加仓（控制极端仓位）
context.LAYER_FRACTION       = 0.08  # 最小层间权重（保守加仓）
context.VOL_WEIGHT           = 0.50  # 波动率与基本面各占 50%（均衡选股）
context.REBALANCE_FREQ       = 10    # 双周频换股（10 交易日）
```

**参数规律解读：**
- `MAX_HOLD=10` → 在正确的股票+ETF混合候选池中，集中持仓头部标的
- `VOL_WEIGHT=0.50` → 修复 bug 后，基本面质量与波动率同等重要
- `REBALANCE_FREQ=10` → 双周换股，捕捉短周期轮动机会

### 5.4 全量回测两个异常现象分析

**① 最大回撤 -48.47%（偏高）**

主要发生在 2021-2022 年 A 股大熊市（沪深300+中证500 同期最大跌幅约 40-50%）。  
网格策略天然弱点：价格持续单边下行时不断补仓，导致越跌越重。  
→ **v2.0 改进方向：加入趋势过滤，大盘持续下行时暂停网格补仓**

**② 平均持仓仅 13.9 只（设计值 50 只）**

标的筛选过严：PE 过滤（0-120）+ 市值（>3亿）+ ROE 要求，在 2019-2022 期间符合条件的股票不足。  
持仓过少导致分散化失效，策略退化为集中持股。  
→ **v2.0 改进方向：放宽或动态调整筛选条件；优先从实际候选池大小反推 MAX_HOLD**

## 八、关键结论

1. **策略有效**：2025-2026 样本外年化 +11.99%，夏普 0.70，具备实际使用价值
2. **最优参数偏向宽步长+保守加仓**：适合 A 股高波动环境，熊市少补仓控回撤
3. **月频换股优于高频**：降低换手成本，稳定持仓
4. **主要风险在熊市**：策略不含趋势过滤，持续下行时回撤较大
5. **持仓数量不足**：实际仅 13.9 只，未达设计 50 只，分散化效果打折

| 优先级 | 方向 | 具体内容 |
|---|---|---|
| 🔴 高 | 熊市保护 | 加入大盘趋势判断（如 MA120），下行趋势时减仓/停止补仓 |
